## Product and safety intent

RustBridge is a native Rust/egui app that teaches genuine Rust source to Java 8 developers.
Rust source and the actual filesystem are authoritative; Java projections remain **read-only explanatory approximations**. Opening a project never implicitly executes its code.

This document records independent **implementation**, **unit/regression validation**, and **real-platform acceptance**. A green CI or a built package is not sufficient to claim human-verified daily usability.

## Windows/macOS write semantics

Linux uses same-directory staged write + fsync + verified xattrs/ACL + rename and directory sync. It remains vulnerable to the last-moment race from a writer **not** using RustBridge's cooperative lock.

On Windows and macOS a source is opened via a stable writable handle; Windows denies competing opens for the duration of save. macOS additionally compares the live path's device/inode to the open handle before and after the in-place transaction, rejecting atomic external path replacement. Existing ownership, ACLs and alternate metadata are not replaced by a new inode. Prior to truncation an independent user-private backup is written and synced. Errors are rolled back where possible; a machine power failure *during* an in-place write can still leave an incomplete source, with the independent backup serving as recovery. Windows session/journal replacement uses the native MoveFileExW replacement API rather than relying on rename-over-existing semantics. Never claim this as fully equivalent to atomic replace, and never silently overwrite a pre-existing recovery copy.

## Release

PR validation is in .github/workflows/rust.yml. Every native OS must pass:
fmt/check/test/clippy, real rust-analyzer LSP and Cargo subprocess integration, Release compilation, and package verification. Linux additionally passes Xvfb real-keyboard source save, CRLF preservation, SIGKILL/relaunch recovery and idle CPU/RSS/fd resource smokes.

Use .github/workflows/soak.yml for manual/weekly endurance. A v-prefixed tag triggers .github/workflows/release.yml and publishes **draft** GitHub Release artifacts for Linux, macOS and Windows. Native Windows installer and macOS bundle are unsigned/unnotarized and may require explicit user approval to run. Do not promote a draft until signing, security review, realistic workload testing and human UX acceptance are complete.

Merge **only once** from the single feature branch into default main after independently observed required CI and acceptance. No automatic publish or remote execution on opening untrusted project source.
