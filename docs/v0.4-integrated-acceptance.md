# RustBridge v0.4 — Single-branch integrated safety and release acceptance

2026-11-04 · Based on PR #20, branch `fix/rustbridge-integrated-hardening-20261104`

## Purpose

Close the remaining findings of the v0.3 critical review **within the same PR and branch**. This is a native Rust learning IDE; its Java view is a read-only, approximate educational guide. Rust source files and actual project directories remain authoritative.

## Commands

```bash
cargo fmt --check
cargo check --all-targets
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo build --release
xvfb-run -a -s '-screen 0 1440x900x24' bash tests/gui-smoke.sh ./target/release/rustbridge
xvfb-run -a -s '-screen 0 1440x900x24' bash tests/resource-smoke.sh ./target/release/rustbridge
bash scripts/package-deb.sh --skip-build
# Package also extracted and exercised from CI in an isolated X11 display.
```

A successful compiled binary alone does not prove GUI functionality: the smoke script actually focuses the window, switches modes, edits a real temporary Rust file, saves via Ctrl+S and verifies its physical contents and the original CRLF line endings. It explicitly unsets `WAYLAND_DISPLAY` so it operates on the Xvfb instance, not the developer's Wayland session.

The v0.4 native binary and Debian package **do not bundle or distribute font files**. Chinese fallback is supplied by available system fonts only.

## Important limitations

- Linux-style metadata preservation is conservative and **fail closed** on unsupported platforms. Preserving ACL, security labels or special metadata may be denied by filesystem privileges; in that case the save is rejected rather than silently dropping attributes. This is not a universal POSIX/Windows/macOS metadata preservation guarantee.
- Atomic rename remains subject to a narrow TOCTOU race against *uncooperative* external writers between final comparison and rename; strict cooperative locks or compare-and-swap transactions are not implemented.
- `CommittedDurabilityUncertain` means the file **was replaced** but durable directory persistence could not be confirmed, not that the save was rolled back.
- File I/O is off the GUI thread for opening/saving a file, but OS dialogs and some lightweight metadata queries still run within GUI interaction. Slow/uninterruptible network file operations cannot be forcibly terminated once started in the worker. Newer open requests supersede prior reads only at chunk boundaries.
- AST declaration search lists *possible* same-name declarations only, not semantic identity. It is bound by file count/depth/file-size/result limits and ignores unsupported macro-derived definitions. No full rust-analyzer LSP, semantic Java compiler, complete cross-file resolution or debugger.
- Xvfb automation and Debian package cover **Linux** only, not real-user Wayland, Windows, macOS, installer upgrade, or long-term 24h memory leak testing. Idle CPU samples are environment-specific and should not be generalized as 0% on all hardware.
- Large files use a 240-line page to bound editor layout; Rust-only editing and Java teaching conversion remain partial rather than a complete general IDE.

## Git workflow

Keep all v0.4 edits on `fix/rustbridge-integrated-hardening-20261104`. After local and GitHub PR checks pass, merge **once** into the actual default `main` branch. Do not create a series of per-issue PRs. The original v0.3 report remains at `docs/hardening-2026-11-04.md`.


### GitHub-hosted Ubuntu X11 dependency

The initial GitHub CI run exposed a missing dynamic X11 runtime library
(`libxkbcommon-x11.so`) despite passing the Rust compiler and tests.
The Linux workflow now explicitly installs `libxkbcommon-x11-0`, and the
Debian package declares it as a runtime dependency. The GUI script detects
an early process crash rather than waiting for a window timeout.


### GitHub Xvfb focus race

A later GitHub runner revealed that a window can be matched by title before its X11
window is actually viewable, causing `X_SetInputFocus BadMatch`. The GUI smoke now
finds only visible windows and retries focus with a verified focus owner. It also
waits for source input to settle before save, tries a second keyboard save if the
virtual input system drops the first chord, and verifies the actual Rust file bytes.
The explicit Save button remains a fallback for the paginated-editor smoke, while
the small-file scenario still requires Ctrl+S to work.

On the developer's Linux Xvfb, four consecutive full small + 35k-line CRLF editor
runs passed after the focus fix. This is repeatability evidence on one environment,
not a guarantee for all CI runner timing scenarios.
