# RustBridge 优化里程碑 — 2026-11-10

本节点记录直接在 `main` 上完成的一轮性能、取消和文件导航可靠性修复。RustBridge 仍保持原生 Rust 桌面应用，真实 Rust 文件是唯一可编辑事实来源，Java 视图仍是只读的保守学习投影。

## 已完成

- 目录索引与文件搜索改为有界的后台遍历，减少宽目录的待处理状态，并在查询清空、项目切换和新查询开始时取消过期任务。
- 文件名搜索支持深度优先迭代器栈，保持 12 层深度和 100 条结果上限；界面明确显示限制，避免误认为结果完整。
- 符号搜索在 Tree-sitter 解析和声明遍历期间响应取消，项目切换不会继续展示旧项目结果。
- 已打开文档优先使用已知路径和文档状态，避免切换标签时重复 canonicalize、重复读取和重复比较完整源文本。
- 搜索与诊断结果不再在每帧复制完整集合；大文件编辑、CRLF/UTF-8 保存和既有恢复安全约束保持不变。
- 增加宽目录微基准：10,000 个空目录下，待处理状态由 10,000 降至 2；RSS 中位数约由 2,992 KiB 降至 2,036 KiB。该基准是隔离遍历测试，不等同完整 GUI 项目扫描。

## 尚未完成

- 仍缺少真实用户桌面上的人工 Linux GUI 验收，以及 Windows/macOS 人工交互、IME、签名和公证证据。
- 启动时间、连续编辑 CPU/RSS、频繁切换文件、长时间运行和真实小/中型 Cargo 项目的可重复性能基线仍不完整；现有数字是明确方法下的局部样本，不能宣称全场景达标。
- rust-analyzer 仍是可选能力；诊断、补全和定义跳转的真实项目体验需要独立验收。
- 大型结构导航、课程内容扩展、复杂宏和不完整语法的解释边界仍需后续产品工作。
